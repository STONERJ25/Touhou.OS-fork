# PC-98 emulation groundwork ("Hakurei emulator")

The owner wants to play their own PC-98 games on TouhouOS some day. This page covers the first step: host-side, tested
pieces that a later OS application can link. Branch `cloud/pc98` (task 18 of the cloud agents' task list).

## The rule: no ROM, no game data, ever

Nothing from a real PC-98 goes into this repository: no BIOS or BASIC ROM, no font ROM (kanji or ANK), no boot
sectors, no disk images, no game data of any kind ([ASSETS.md](ASSETS.md)). Every test program here was written for
these tests (nasm source under `tests/host/`, or bytes assembled by hand), and every disk image is synthesized by the test
that uses it. The ROM area of the emulated machine reads as FFh. The user's own disk images belong in `assets/local/`
(git-ignored) or on their own volume, never in the tree.

The optional cross-check (`tests/host/x86sst.py`) downloads the MIT-licensed SingleStepTests 8088 vectors at test time
into `build/sst-8088/`, and the SingleStepTests 80386 real-mode vectors (MIT software, public-domain data) into
`build/sst-80386/` (both git-ignored); they are not committed.

## What exists

Everything lives in one freestanding library, `user/lib/pc98/` (`libpc98.a`). It uses `<stdint.h>`, `<stddef.h>`,
`memset` and `memcpy` only and allocates nothing, so it builds with libgap; `tools/build.py` already picks it up like
every `user/lib/*` (it is linked into no program yet; the archive only costs what a program references).

| File | What |

### CPU core (`x86emu`)

- **Interface:** memory, ports and INTR through callbacks (`X86Bus`), one instruction per `x86_step()` (a REP string
  instruction runs one iteration per step and leaves IP on its first prefix until done, so interrupts land between
  iterations), `x86_run()` with a cycle budget, NMI, a `soft_int` hook for high-level BIOS emulation later, a trace hook.
- **8086:** every documented instruction; exact flags including AF, OF and PF; the undocumented behaviours programs rely
  on: SALC (D6), POP CS (0F), the 60-6F / C0 / C1 / C8 / C9 aliases, SETMO/SETMOC (D0-D3 /6), 82 = 80, F6/F7 /1 = TEST,
  FF /7 = PUSH, 8C/8E with reg 4-7 (two bits decoded), C6/C7 ignoring reg, shift counts not masked (up to 255 steps),
  PUSH SP pushing the decremented value, divide errors pushing the address of the *next* instruction, IDIV refusing a
  -128/-32768 quotient, a REP prefix negating IDIV's quotient, the flags DAA/DAS really produce (the 9Fh threshold when
  AF came in set), the flags a divide error leaves (those of the first subtraction step), AAM 0. Interrupt shadow after
  MOV/POP to a segment register and after STI; TF single step (the instruction that clears TF still traps); HLT.
  Word accesses wrap inside the segment; addresses wrap at 1 MiB.
- **V30 (and V20):** the 80186 additions (PUSHA, POPA, BOUND, PUSH imm, IMUL imm, INS/OUTS, ENTER, LEAVE, shifts by an
  immediate, 5-bit shift counts), TEST1/CLR1/SET1/NOT1, ROL4/ROR4, the REPC/REPNC prefixes, AAM/AAD always using base 10.
  FLAGS bits 12-15 read as 1.
- **80286 real mode:** the 186 additions, FLAGS bits 12-15 reading 0, PUSH SP pushing the old value, divide error
  pointing at the faulting instruction, the invalid opcode trap (INT 6) for 63-67, F1, FE/FF with bad reg fields, LEA/LES/
  LDS with a register operand, MOV CS; SMSW, LMSW (setting PE stops the CPU: `X86_STOP_PROTECTED`); A20 through
  `addr_mask` (24-bit when open). AAA/AAS add/subtract on AX as a whole.
- **80386 and 80486 real mode** (`X86_MODEL_80386`, `X86_MODEL_80486`): a separate interpreter, `src/x86cpu32.c`, that
  `x86_step()`, `x86_reset()` and `x86_interrupt()` hand these models to, so the 8086/V30/286 decoder above is untouched.
  - *Instruction set:* the operand-size (66h) and address-size (67h) prefixes; 32-bit registers (`r[]` keeps AX..DI, the
    upper halves live in `rh[]` and survive 8- and 16-bit operations; `x86_reg32()`, `x86_set_reg32()`, `x86_eflags()`);
    32-bit addressing with SIB bytes; FS and GS (64h/65h, MOV, PUSH/POP, LFS/LGS/LSS); the 0F page: Jcc near, SETcc,
    MOVZX/MOVSX, SHLD/SHRD, BT/BTS/BTR/BTC with memory bit strings, BSF/BSR, IMUL r, r/m; CWDE/CDQ, PUSHAD/POPAD,
    PUSHFD/POPFD, IRETD, 32-bit MUL/IMUL/DIV/IDIV, string instructions on ECX/ESI/EDI under 67h, LOOP/JCXZ counting CX or
    ECX by the address size, 32-bit I/O as two word accesses (the C-bus is 16 bits wide), SALC, ICEBP (F1: INT 1). The
    486 adds BSWAP, XADD, CMPXCHG (0F B0/B1), INVD, WBINVD and INVLPG (no-ops: no cache, no TLB).
  - *Real-mode protection:* every segment keeps the 64 KiB limit of the reset state (nothing can change it without
    protected mode), so an operand that does not end at or below FFFFh raises #GP (INT 0Dh), or #SS (INT 0Ch) in the
    stack segment: a word at FFFFh faults instead of wrapping. The second part of a far pointer, a BOUND pair or a
    descriptor-table operand wraps at 64 KiB with 16-bit addressing and is checked on its own. A jump, call or return
    to an offset above FFFFh with a 32-bit operand size is a #GP; an instruction that ends at FFFFh leaves EIP at 10000h
    and the next fetch faults (IP 0 pushed). More than 15 instruction bytes: #GP. Invalid opcodes raise #UD (INT 6):
    0F 00, LAR, LSL, ARPL, CPUID, RSM, the Pentium page, the register forms of LEA/LES/LDS/LSS/LFS/LGS/BOUND, 8F/C6/C7
    with reg 1-7, FE /2-7, FF /7, MOV to CS and to segment registers 6/7, and LOCK on anything but a read-modify-write
    of memory (BT, CMP, TEST and MOV are not lockable). Faults restore the registers (each instruction runs on a
    snapshot; writes and port accesses stop at the fault) and push the faulting instruction's IP. A fault while
    entering a fault (an odd SP below 6, an IDT limit too small for both #GP and #DF) shuts the CPU down
    (`X86_STOP_SHUTDOWN`).
  - *System registers:* CR0 (386: MP, EM, TS, ET, reserved bits 5-30 read as ones; 486: also NE, WP, AM, NW, CD, ET
    always set; PG without PE and the 486's NW without CD are #GP; setting PE stops the CPU with `X86_STOP_PROTECTED`),
    CR2, CR3, DR0-DR7 (DR4/DR5 alias DR6/DR7; no breakpoints), TR6/TR7 (TR3-TR7 on the 486), LGDT/LIDT/SGDT/SIDT (a
    16-bit operand size loads a 24-bit base and stores a zero top byte; the 286 stored FFh), SMSW/LMSW, CLTS. Real-mode
    interrupts read their vectors through the IDTR (LIDT moves the table; a vector beyond the limit is a #GP at the
    INT), before the frame is pushed, and push FLAGS, CS and IP as words whatever the operand size. LOADALL (0F 07)
    stops the CPU with `X86_STOP_UNIMPLEMENTED` (`bad_opcode` 0Fh, `bad_opcode2` 07h).
  - *FLAGS:* IOPL and NT can be written in real mode and bit 15 cannot (the 286/386 test of every CPU-detection routine);
    the 486's AC flag (EFLAGS bit 18) can be set and the 386's cannot; the ID flag (bit 21) cannot on either, so
    software sees no CPUID; interrupts clear AC.
  - *What only the hardware says* (the SingleStepTests 80386 vectors, recorded on a 386EX; every vector agrees): a 32-bit
    PUSH/POP of a segment register moves SP by 4 but touches only the selector's word; POPAD on the 16-bit stack loads
    ESP's upper half from the saved image, and a stack fault part-way keeps the registers already popped; PUSHAD writes
    its block from the lowest address up and an operand across the wrap raises #SS (not the #GP the manual lists),
    leaving the lower part written; 32-bit ENTER zero-extends the frame pointer into EBP; 16-bit SHLD/SHRD with counts
    above 16 shift dst:src:src and src:src:dst; the SIB scale applies to the base register when the index is 100b
    (assumed not on the 486); a REP string instruction runs its later iterations from the decoded form, so one that
    overwrites its own bytes carries on; the vector of an interrupt is read before the frame is pushed. Flags the
    manuals call undefined: logic instructions clear AF, SHL/SHR/SAR/SHLD/SHRD set it; OF after a multi-bit shift is
    the single-bit formula applied to the result (0 for SHR and SAR), after SHLD MSB xor CF, after SHRD the top two
    result bits xor'ed; CF of SHL/SHR past the width is 0, except that a byte shifted by 16 or 24 gets the CF of a shift
    by 8; DAA/DAS set OF to the signed overflow of the adjustment; AAA/AAS take SF/ZF/PF from AL plus or minus 6 before
    the mask and OF from that addition; AAM clears OF/AF/CF; AAD's flags are those of its addition; BT* leave
    SF/ZF/AF/PF alone; IDIV clears OF.
  - *Known differences from the 386EX vectors* (29 of 1.76 million; see the tests table): a REP STOSW/MOVS that
    overwrites the instructions just after it (the 386 runs the old bytes from its prefetch queue; there is no queue
    here: 4 vectors); byte IDIVs whose quotient overflows yet which the 386 completes with AL = 80h instead of a #DE (9
    vectors, no rule found); the flags AAM 0 leaves before its #DE (10 vectors, no rule found); IN from ports 1Fh-24h,
    where the 386EX's own interrupt controller answers (not a CPU property: 6 vectors).
  - *Not modelled or unverified:* the other undefined flags of MUL, IMUL (all forms), DIV, IDIV, BSF/BSR and BT* (OF):
    the vectors show they come out of the multiplier and divider microcode, with no rule a simple formula matches; here
    MUL/IMUL set SF/ZF/PF from the low half and the rest stay as they were (a program that tells an Intel chip from a
    Cyrix by the flags a DIV leaves would see a Cyrix). No FPU: ESC instructions decode their operand and do nothing
    (#NM when CR0.EM or TS asks; WAIT traps with MP and TS), except that FNSTSW AX and FNSTSW/FNSTCW to memory deliver
    FFFFh, the value of an empty coprocessor bus, so the usual probes find no FPU whatever the program preset
    (unverified; the 486 is a 486SX here). The component ID in DX after reset (0308h, 0422h) and the 486's choices
    (its undefined flags are taken to be the 386's) are unverified. Unreal ("big real") mode, protected mode, V86 mode,
    paging, task switches, debug breakpoints, prefetch queues and caches are not modelled (phase 2 of
    the project's internal briefs).
- **Cycle counter:** approximate. 8086 data sheet values (the middle of a range) plus the effective-address cost and 2 per
  prefix; no prefetch queue, no wait states, no 8088 bus penalty, the same table for the V30 and 286 (both are faster in
  reality). Good enough to pace the timer and VSYNC, not for cycle-exact tricks. The 386 and 486 use their own data
  sheets' counts for the common case (the 486 is faster, but pays a clock per prefix; a taken jump costs the 386 three
  clocks for the next instruction's decode).
- **Missing:** protected mode; the 8087 (ESC opcodes decode their operand and do nothing; WAIT is a no-op); the V30's
  8080 emulation mode (BRKEM), its BCD string instructions (ADD4S, SUB4S, CMP4S) and bit-field instructions (INS, EXT),
  which stop the CPU with `X86_STOP_UNIMPLEMENTED`; V30 opcodes 63/66/67 are treated as one-byte no-ops (unverified);
  SALC is kept on the V30 (unverified); the 8086 bug that loses all but one prefix when a REP instruction is interrupted
  (we restart from the first prefix); the 8086's undefined FE /2-7 (stops the CPU); the flags an IDIV leaves when its
  quotient overflows only at the end of the division (undefined bits, they keep their old values); whether a single-step
  trap follows an INT n (we take it at the handler's first instruction; unverified).

### Machine skeleton (`pc98`)

`Pc98` is about 1 MiB (allocate it). `pc98_init(m, model, cpu_hz)`, `pc98_boot(m, &disk, da_ua)`, `pc98_run(m, cycles)`,
`pc98_dead(m)`, `pc98_key()`, `pc98_text_dump()`, `pc98_render(m, rgb, stride)` (fonts: `pc98gfx_set_font(&m->gfx, ...)`).

**Since 2026-11-03 the display belongs to `pc98gfx`** ([PC98_GFX.md](PC98_GFX.md)): the memory table and the port table below
describe the machine as it was; the rows for A0000-A4FFF, A8000-BFFFF, E0000-E7FFF, the GDC ports 60h/62h/A0h/A2h, 68h-6Ch, 70h-7Ah,
A4h-AEh are now the module's, and it adds 7Ch/7Eh (GRCG), A1h/A3h/A5h/A9h (character generator), 4A0h-4AFh (EGC). The machine tries
`pc98gfx_port_read/write` (and `pc98gfx_mem_*` for memory) after its own cases; 64h (the VSYNC interrupt) stays here. The CPU cores call
the optional `X86Bus.read16/write16` for word operands, so a word at an even graphics address reaches the EGC as one operation. The
GDC status bits come from the live clock (VSYNC for the first 1/11 of a 56.42 Hz frame, HBLANK for the last fifth of each of 440
lines), not from the last 256-cycle slice. `pc98_attach_opna(m, &fm, OPNA_BOARD_86, 12)` puts the FM board on ports 188h-18Eh/A460h
with its interrupt on IRQ 12 and keeps it at the CPU's clock (`m->fm`); that function is written but **has no test yet** (the sound
tests drive the board through the machine's host port hooks, in `opnatool`).

Memory map: 00000-9FFFF RAM (640 KiB); A0000-A1FFF text VRAM (one word per cell, 80x25); A2000-A3FFF attributes
(bit 0 visible, 1 blink, 2 reverse, 3 underline, 4 vertical line, 5-7 B R G); A4000-A4FFF character generator window
(no font ROM: FFh); A8000/B0000/B8000 graphics planes B, R, G and E0000 plane I, two pages (A6h selects the page the CPU
sees, A4h the one displayed); everything else, including the BIOS area E8000-FFFFF, reads FFh.

| Port | Device | Behaviour here |
|------|--------|----------------|
| 00h, 02h / 08h, 0Ah | 8259A master / slave (slave on master IR7) | ICW1-4, IMR, IRR/ISR reads, fixed priority, (specific) EOI, AEOI, level/edge, special mask; no rotation, no poll |
| 31h, 33h, 35h, 37h | 8255 system port | port C read/write and bit set/reset; bit 3 is the beeper (0 = on); DIP switches read FFh |
| 41h, 43h | uPD8251 keyboard | mode/command protocol, 32-byte key queue, RxRDY status, IRQ 1; key up = code + 80h |
| 50h, 52h | NMI mask | stored |
| 5Fh | wait port | ignored |
| 60h, 62h / A0h, A2h | uPD7220 text / graphics GDC | status (FIFO empty, data ready, VSYNC), RESET/SYNC/BCTRL/START display on/off, PITCH, ZOOM, CSRFORM, MASK, CSRW + CSRR, PRAM; drawing and VRAM commands counted, not carried out |
| 64h | CRT interrupt reset | arms one VSYNC interrupt (IRQ 2) |
| 68h, 6Ah, 6Ch | mode flip-flops 1 and 2, border | stored; 6Ah selects the 16-colour analog palette |
| 70h-7Ah even | text CRTC | ignored |
| 71h, 73h, 75h, 77h (also 3FD9h-3FDFh) | 8253 | modes 0-5 (1/5 behave as 0/4, 3 counts like 2), latch, LSB/MSB/both, BCD reload; counter 0 = IRQ 0, counter 1 = beeper tone; clock 2.4576 MHz, or 1.9968 MHz when the CPU clock is a multiple of 8 MHz |
| A4h, A6h | display / draw page | |
| A8h-AEh | palette | digital (two GRB nibbles per port) or analog (index, G, R, B) |
| F0h | CPU reset | counted only (needs the BIOS resume path) |
| F2h, F6h | A20 gate | `addr_mask` on a 286 |

Anything else: reads FFh, writes dropped, counted in `unhandled` (a host hook can claim ports). VSYNC: 56.42 Hz frames,
the VSYNC bit set for the first 1/11 of each frame (approximate). The text screen starts the way the BIOS leaves it
(spaces, white, visible), the text GDC on, the graphics GDC off.

Bare boot hand-over, `pc98_boot()` (for the synthetic demos; no BIOS): the first sector (C0 H0 R1) is loaded to 1FC0:0000, then
CS = DS = ES = SS = 1FC0h, SP = 0, AL = DA/UA (90h first 1 MB floppy, 80h first hard disk), interrupts off. The interrupt
vector table is left empty: a boot program that enables interrupts installs its own handlers. The convention a real IPL
needs (found by observation: DS = 0, the DA/UA in `[0000:0584]`, entered by a far call) is `pc98_bios_boot()` of the HLE
BIOS, [PC98_BIOS.md](PC98_BIOS.md).

### Disk images (`pc98disk`)

The caller owns the bytes; nothing is copied or allocated; every header field is checked against the size.

- **D88:** name, write protect, media type, 164- or 160-entry track tables, multi-disk files (the image ends at its
  own size field); sectors looked up by ID like an FDC (preferring matching C/H), recorded order, deleted marks, FDC
  status, FM/MFM density, mixed sector sizes.
- **FDI / HDI** (Anex86): the eight-word header, geometry, data after `header size`.
- **Raw:** 1232 KiB 2HD (77x2x8x1024), 1.44 MB, 1.2 MB 2HC, 720 KiB, 640 KiB.
- Detection without a hint: an Anex86 header whose sizes add up to the file, then D88, then a looser Anex86 match, then
  raw sizes. FDI vs HDI by geometry (2 heads or fewer and at most 90 cylinders = floppy) unless the caller says.
- **Missing:** NFD, NHD, HDM variants with other geometries, writing, copy-protection details beyond what D88 records.

## Public references

Intel *8086 Family User's Manual* (instruction set, timing table), Intel *80286 Programmer's Reference*, Intel *80386
Programmer's Reference Manual* and *i486 Microprocessor Programmer's Reference Manual* with the two chips' data sheets
(instruction set, real-address-mode exceptions, system registers, clock counts), NEC *V20/V30 User's Manual* (the extra
instructions), the uPD7220, uPD8251, 8253 and 8259A data sheets, the SingleStepTests 8088 and 80386 vector notes
(https://github.com/SingleStepTests/8088 and /80386, MIT; the MOO file format: https://github.com/dbalsom/moo,
doc/moo_format_v1.md, from which x86sst.py's reader was written), and the publicly documented PC-98 port and memory
maps (the community's undocumented-PC-98 notes). Values taken from memory of such documents and not verified against hardware are
marked "unverified" above; the digital palette nibble order and the boot register values are the main ones.

## How to resume

1. `python3 -m unittest discover -s tests/host -p "test_*.py"`; after CPU changes also `python3 tests/host/x86sst.py --fetch --limit 0`
   (about 400 MB of downloads into `build/sst-8088/`, 20-40 minutes), and after 386/486 changes
   `python3 tests/host/x86sst.py --cpu 386 --fetch --limit 0` (about 600 MB into `build/sst-80386/`, about 40 minutes).
2. The road to an OS application ("Hakurei emulator", a Kappa app): a window of 640x400 fed by `pc98_render()` with the
   OS's own 8x16 font for the text layer (`shared/font8x16.c`; kanji need task 17's double-width font); keys mapped from
   `KEY_*` to PC-98 key codes into `pc98_key()`; disk images opened from `assets/local/` or `/HumanVillage`; the beeper
   state (`beep_on`, `pc98_beep_hz()`) into the audio library; a frame loop of `pc98_run(m, cpu_hz / 56)`.
3. Next machine pieces, roughly in the order software needs them: the uPD765 floppy controller and the BIOS disk calls as
   high-level emulation through `X86Bus.soft_int` (INT 1Bh), the CRT BIOS (INT 18h: keyboard read, text/graphics on,
   cursor), GRCG (7Ch/7Eh) and EGC raster operations, GDC drawing commands, the calendar clock, DMA, the mouse (7FD9h-
   7FDFh), YM2203/YM2608 sound. Kanji text needs a font the user supplies or an original one; never a ROM dump.
4. CPU: the V30 BCD string and bit-field instructions if a program needs them; prefetch-queue timing only if something
   breaks without it. The Touhou games (TH01-TH05) need the 386 real-mode set and nothing from the 486 (their startup
   code probes FLAGS bits 12-15 and the AC flag, which the 386/486 models answer as the chips do). Protected mode, V86
   and paging (phase 2 of the project's internal briefs) matter for TH04's `CONFIG.SYS`, which loads `HIMEM.SYS` and
   `EMM386.EXE /UMB`: HIMEM's 386 copy routine also relies on the #GP of an offset above FFFFh to switch into big real
   mode, which needs protected-mode descriptor loads. The machine's A20 gate (`pc98mach.c`) opens the address mask only
   for the 286 model so far; the 386/486 models need the same (`model >= X86_MODEL_80286`).
