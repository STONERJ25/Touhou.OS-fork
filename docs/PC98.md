# PC-98 emulation groundwork ("Hakurei emulator")

The owner wants to play their own PC-98 games on TouhouOS some day. This page covers the first step: host-side, tested
pieces that a later OS application can link. Branch `cloud/pc98` (task 18 of [CLOUD_AGENT_BRIEF.md](CLOUD_AGENT_BRIEF.md)).

## The rule: no ROM, no game data, ever

Nothing from a real PC-98 goes into this repository: no BIOS or BASIC ROM, no font ROM (kanji or ANK), no boot
sectors, no disk images, no game data of any kind ([ASSETS.md](ASSETS.md)). Every test program here was written for
these tests (nasm source under `tests/host/`, or bytes assembled by hand), and every disk image is synthesized by the test
that uses it. The ROM area of the emulated machine reads as FFh. The user's own disk images belong in `assets/local/`
(git-ignored) or on their own volume, never in the tree.

The optional cross-check (`tests/host/x86sst.py`) downloads the MIT-licensed SingleStepTests 8088 vectors at test time
into `build/sst-8088/` (git-ignored); they are not committed.

## What exists

Everything lives in one freestanding library, `user/lib/pc98/` (`libpc98.a`). It uses `<stdint.h>`, `<stddef.h>`,
`memset` and `memcpy` only and allocates nothing, so it builds with libgap; `tools/build.py` already picks it up like
every `user/lib/*` (it is linked into no program yet; the archive only costs what a program references).

| File | What |
|------|------|
| `include/x86emu.h`, `src/x86cpu.c` | the CPU core: 8086, NEC V30, 80286 real mode |
| `include/pc98.h`, `src/pc98mach.c` | the machine: memory map, I/O dispatcher, device timing, boot hand-over, text dump, renderer |
| `src/pc98dev.c` | 8259A, 8253, uPD7220 bookkeeping |
| `include/pc98disk.h`, `src/pc98disk.c` | D88, FDI, HDI and raw disk images |

### CPU core (`x86emu`)

- **Interface:** memory, ports and INTR through callbacks (`X86Bus`), one instruction per `x86_step()` (a REP string
  instruction runs one iteration per step and leaves IP on its first prefix until done, so interrupts land between
  iterations), `x86_run()` with a cycle budget, NMI, a `soft_int` hook for high-level BIOS emulation later, a trace hook.
- **8086:** every documented instruction; exact flags including AF, OF and PF; the undocumented behaviours programs rely
  on: SALC (D6), POP CS (0F), the 60-6F / C0 / C1 / C8 / C9 aliases, SETMO/SETMOC (D0-D3 /6), 82 = 80, F6/F7 /1 = TEST,
  FF /7 = PUSH, 8C/8E with reg 4-7 (two bits decoded), C6/C7 ignoring reg, shift counts not masked (up to 255 steps),
  PUSH SP pushing the decremented value, divide errors pushing the address of the *next* instruction, IDIV refusing a
  -128/-32768 quotient, a REP prefix negating IDIV's quotient, the flags DAA/DAS really produce (the 9Fh threshold when
  AF came in set), the flags a divide error leaves (those of the first subtraction step), AAM 0. Interrupt shadow after
  MOV/POP to a segment register and after STI; TF single step (the instruction that clears TF still traps); HLT.
  Word accesses wrap inside the segment; addresses wrap at 1 MiB.
- **V30 (and V20):** the 80186 additions (PUSHA, POPA, BOUND, PUSH imm, IMUL imm, INS/OUTS, ENTER, LEAVE, shifts by an
  immediate, 5-bit shift counts), TEST1/CLR1/SET1/NOT1, ROL4/ROR4, the REPC/REPNC prefixes, AAM/AAD always using base 10.
  FLAGS bits 12-15 read as 1.
- **80286 real mode:** the 186 additions, FLAGS bits 12-15 reading 0, PUSH SP pushing the old value, divide error
  pointing at the faulting instruction, the invalid opcode trap (INT 6) for 63-67, F1, FE/FF with bad reg fields, LEA/LES/
  LDS with a register operand, MOV CS; SMSW, LMSW (setting PE stops the CPU: `X86_STOP_PROTECTED`); A20 through
  `addr_mask` (24-bit when open). AAA/AAS add/subtract on AX as a whole.
- **Cycle counter:** approximate. 8086 data sheet values (the middle of a range) plus the effective-address cost and 2 per
  prefix; no prefetch queue, no wait states, no 8088 bus penalty, the same table for the V30 and 286 (both are faster in
  reality). Good enough to pace the timer and VSYNC, not for cycle-exact tricks.
- **Missing:** protected mode; the 8087 (ESC opcodes decode their operand and do nothing; WAIT is a no-op); the V30's
  8080 emulation mode (BRKEM), its BCD string instructions (ADD4S, SUB4S, CMP4S) and bit-field instructions (INS, EXT),
  which stop the CPU with `X86_STOP_UNIMPLEMENTED`; V30 opcodes 63/66/67 are treated as one-byte no-ops (unverified);
  SALC is kept on the V30 (unverified); the 8086 bug that loses all but one prefix when a REP instruction is interrupted
  (we restart from the first prefix); the 8086's undefined FE /2-7 (stops the CPU); the flags an IDIV leaves when its
  quotient overflows only at the end of the division (undefined bits, they keep their old values); whether a single-step
  trap follows an INT n (we take it at the handler's first instruction; unverified).

### Machine skeleton (`pc98`)

`Pc98` is about 1 MiB (allocate it). `pc98_init(m, model, cpu_hz)`, `pc98_boot(m, &disk, da_ua)`, `pc98_run(m, cycles)`,
`pc98_dead(m)`, `pc98_key()`, `pc98_text_dump()`, `pc98_render()`.

Memory map: 00000-9FFFF RAM (640 KiB); A0000-A1FFF text VRAM (one word per cell, 80x25); A2000-A3FFF attributes
(bit 0 visible, 1 blink, 2 reverse, 3 underline, 4 vertical line, 5-7 B R G); A4000-A4FFF character generator window
(no font ROM: FFh); A8000/B0000/B8000 graphics planes B, R, G and E0000 plane I, two pages (A6h selects the page the CPU
sees, A4h the one displayed); everything else, including the BIOS area E8000-FFFFF, reads FFh.

| Port | Device | Behaviour here |
|------|--------|----------------|
| 00h, 02h / 08h, 0Ah | 8259A master / slave (slave on master IR7) | ICW1-4, IMR, IRR/ISR reads, fixed priority, (specific) EOI, AEOI, level/edge, special mask; no rotation, no poll |
| 31h, 33h, 35h, 37h | 8255 system port | port C read/write and bit set/reset; bit 3 is the beeper (0 = on); DIP switches read FFh |
| 41h, 43h | uPD8251 keyboard | mode/command protocol, 32-byte key queue, RxRDY status, IRQ 1; key up = code + 80h |
| 50h, 52h | NMI mask | stored |
| 5Fh | wait port | ignored |
| 60h, 62h / A0h, A2h | uPD7220 text / graphics GDC | status (FIFO empty, data ready, VSYNC), RESET/SYNC/BCTRL/START display on/off, PITCH, ZOOM, CSRFORM, MASK, CSRW + CSRR, PRAM; drawing and VRAM commands counted, not carried out |
| 64h | CRT interrupt reset | arms one VSYNC interrupt (IRQ 2) |
| 68h, 6Ah, 6Ch | mode flip-flops 1 and 2, border | stored; 6Ah selects the 16-colour analog palette |
| 70h-7Ah even | text CRTC | ignored |
| 71h, 73h, 75h, 77h (also 3FD9h-3FDFh) | 8253 | modes 0-5 (1/5 behave as 0/4, 3 counts like 2), latch, LSB/MSB/both, BCD reload; counter 0 = IRQ 0, counter 1 = beeper tone; clock 2.4576 MHz, or 1.9968 MHz when the CPU clock is a multiple of 8 MHz |
| A4h, A6h | display / draw page | |
| A8h-AEh | palette | digital (two GRB nibbles per port) or analog (index, G, R, B) |
| F0h | CPU reset | counted only (needs the BIOS resume path) |
| F2h, F6h | A20 gate | `addr_mask` on a 286 |

Anything else: reads FFh, writes dropped, counted in `unhandled` (a host hook can claim ports). VSYNC: 56.42 Hz frames,
the VSYNC bit set for the first 1/11 of each frame (approximate). The text screen starts the way the BIOS leaves it
(spaces, white, visible), the text GDC on, the graphics GDC off.

Boot hand-over (our choice, standing in for the BIOS): the first sector (C0 H0 R1) is loaded to 1FC0:0000, then
CS = DS = ES = SS = 1FC0h, SP = 0, AL = DA/UA (90h first 1 MB floppy, 80h first hard disk), interrupts off. The interrupt
vector table is left empty: a boot program that enables interrupts installs its own handlers.

### Disk images (`pc98disk`)

The caller owns the bytes; nothing is copied or allocated; every header field is checked against the size.

- **D88:** name, write protect, media type, 164- or 160-entry track tables, multi-disk files (the image ends at its
  own size field); sectors looked up by ID like an FDC (preferring matching C/H), recorded order, deleted marks, FDC
  status, FM/MFM density, mixed sector sizes.
- **FDI / HDI** (Anex86): the eight-word header, geometry, data after `header size`.
- **Raw:** 1232 KiB 2HD (77x2x8x1024), 1.44 MB, 1.2 MB 2HC, 720 KiB, 640 KiB.
- Detection without a hint: an Anex86 header whose sizes add up to the file, then D88, then a looser Anex86 match, then
  raw sizes. FDI vs HDI by geometry (2 heads or fewer and at most 90 cylinders = floppy) unless the caller says.
- **Missing:** NFD, NHD, HDM variants with other geometries, writing, copy-protection details beyond what D88 records.

## Tests (host only, no QEMU)

| Command | What | Result on the paused head |
|---------|------|------------------|
| `python3 tests/host/test_x86emu.py` | 37 table-driven tests, one class per instruction group: hand tables plus the Python reference model `tests/host/x86ref.py` (flags from definitions, no shared code), random operands, all three models | 37 pass |
| `python3 tests/host/test_x86progs.py` | nasm programs `tests/host/x86progs/*.asm` (sieve, strings, muldiv, interrupts, bcd, cpu186, cpuid) run to HLT on the models in their header, checked against the `; expect` lines | 7 pass (skipped without nasm) |
| `python3 tests/host/test_pc98.py` | synthesized D88/FDI/HDI/raw images, 400 damaged images under AddressSanitizer, PIC/PIT/GDC/keyboard/beeper/A20/memory map/renderer, boot demos | 16 pass |
| `python3 tests/host/x86sst.py --fetch [--limit N]` | SingleStepTests 8088 v2 vectors (opt-in, network): registers, masked flags, memory | 3,007,000 vectors, 0 failures |

All three unittest files: `python3 -m unittest discover -s tests/host -p "test_*.py"` (they need gcc; the drivers
`tests/host/x86tool.c` and `tests/host/pc98tool.c` are built into `build/host-x86/` with AddressSanitizer and UBSan).

The boot demo (`tests/host/pc98boot/hello.asm`, 512 bytes) boots from a D88 (V30), an HDI (286) and an FDI (8086) and
leaves this on the text screen:

```
Hakurei Shrine boot sector, no ROM inside
boot device (DA/UA): 90
three VSYNCs seen on the text GDC
timer interrupts counted: 05
the beeper sang at 2 kHz
GDC cursor read back: 1234

The barrier holds. Halting.
```

`tests/host/pc98boot/tiny.asm` is a 51-byte sector that the test also carries as hand-assembled bytes, so a boot demo runs
even without nasm.

## Public references

User's Manual* (the extra instructions), the uPD7220, uPD8251, 8253 and 8259A data sheets, the SingleStepTests 8088 vector

community's undocumented-PC-98 notes). Values taken from memory of such documents and not verified against hardware are
marked "unverified" above; the digital palette nibble order and the boot register values are the main ones.

## How to resume

1. `python3 -m unittest discover -s tests/host -p "test_*.py"`; after CPU changes also `python3 tests/host/x86sst.py --fetch --limit 0`
   (about 400 MB of downloads into `build/sst-8088/`, 20-40 minutes).
2. The road to an OS application ("Hakurei emulator", a Kappa app): a window of 640x400 fed by `pc98_render()` with the
   OS's own 8x16 font for the text layer (`shared/font8x16.c`; kanji need task 17's double-width font); keys mapped from
   `KEY_*` to PC-98 key codes into `pc98_key()`; disk images opened from `assets/local/` or `/HumanVillage`; the beeper
   state (`beep_on`, `pc98_beep_hz()`) into the audio library; a frame loop of `pc98_run(m, cpu_hz / 56)`.
3. Next machine pieces, roughly in the order software needs them: the uPD765 floppy controller and the BIOS disk calls as
   high-level emulation through `X86Bus.soft_int` (INT 1Bh), the CRT BIOS (INT 18h: keyboard read, text/graphics on,
   cursor), GRCG (7Ch/7Eh) and EGC raster operations, GDC drawing commands, the calendar clock, DMA, the mouse (7FD9h-
   7FDFh), YM2203/YM2608 sound. Kanji text needs a font the user supplies or an original one; never a ROM dump.
4. CPU: the V30 BCD string and bit-field instructions if a program needs them; prefetch-queue timing only if something
   breaks without it; protected mode only for 286/386 titles.
